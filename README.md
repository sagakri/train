# Симулятор движения поездов — Java

Самостоятельное приложение на **Java 17 и Swing**: моделирует четыре поезда на однопутной X-сети, ищет безопасное расписание и показывает движение. Интерфейс и расчёты реализованы на Java; браузер, JavaScript, Node.js, Maven и сторонние библиотеки для запуска Java-версии не нужны.

Репозиторий содержит Java-версию проекта, скрипты запуска и документацию. Маршруты и контрольные расписания описаны в [ROUTES.md](ROUTES.md).

## Запуск на Windows

Нужен **полный JDK 17+**, включающий `java`, `javac` и `jar`. На текущем компьютере сборка проверена с JDK 17.0.12.

1. Откройте папку проекта.
2. Двойным щелчком запустите **`run.bat`**.
3. Нажмите **«Найти лучший график»** в окне приложения.

Скрипт собирает текущие исходники и запускает приложение. Политика PowerShell меняется только для процесса запуска, системные настройки не изменяются.

Из PowerShell в папке проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

Готовый исполняемый файл: **`dist/train-simulator.jar`**. Запуск без пересборки:

```powershell
java '-Dfile.encoding=UTF-8' -jar dist/train-simulator.jar
```

Для запуска собранного JAR достаточно Java 17+. Для пересборки нужен JDK. Каталоги `out` и `dist` создаются сборкой и не отслеживаются Git.

В IntelliJ IDEA откройте каталог проекта, выберите Project SDK JDK 17+ и language level 17. Если нужно, отметьте `src` как Sources Root. Запустите `main` в `src/train/Main.java`.

Редактируйте ячейку двойным щелчком. Время: секунды (`78.28`) или `ЧЧ:ММ:СС` (`00:01:18.28`); десятичная запятая допустима. Маршрут: узлы через дефисы, например `D-F-O-G-B`. Количества — целые неотрицательные числа.

Вкладки **«Расписание»**, **«События»**, **«Проверка / конфликты»** показывают итоговые маршруты и остановки, интервалы занятия ресурсов, конфликты и точные времена.

Ручная проверка выбранного результата сохраняет рассчитанные ожидания у стрелок. Изменение параметров, времени или маршрута сбрасывает результаты и ожидания. Произвольные длительности остановок отдельно не вводятся: как в исходной версии, их определяет автоматический поиск.

Для сравнения включите и выключите «С вагонами», каждый раз выполните поиск. Сравнение относится к одинаковым физическим параметрам и режиму ожидания.

## Модель и алгоритм

Узлы: `A, B, C, D, E, F, G, S, O`. Центральная точка — латинская буква `O`. Основные рёбра: `A-E`, `E-O`, `O-S`, `S-C`, `D-F`, `F-O`, `O-G`, `G-B`; дополнительные: `E-F`, `E-G`, `F-S`, `G-S`.

Внешние участки `A-E`, `D-F`, `S-C`, `G-B` имеют длину 23 км, остальные — 2 км. `E-G` — отдельное ребро, пересечения рисунка не создают узлов. Длины вагона и цистерны по умолчанию 20 м — исходное допущение проекта. Запас — 1 с.

```text
L = cars * carLength + tanks * tankLength    [метры]
travel = 3600 * distance / speed              [секунды]
tailDelay = 3.6 * L / speed                   [секунды]
```

Каждый участок и узел — ресурс, занятый с входа головы до выхода хвоста. Второй поезд допускается после освобождения плюс запас независимо от направления. Остановка головы задерживает освобождение всех ресурсов, ещё находящихся под составом.

Цель: **минимальное время освобождения сети хвостом последнего поезда**. Сумма ожиданий и километраж отдельно не минимизируются.

DFS перечисляет маршруты без повторения узлов. Для исходной сети: `9 × 8 × 9 × 8 = 5184` сочетания. Метод ветвей и границ рассматривает оба порядка доступа к конфликтующему ресурсу, распространяет ограничения `t[b] >= t[a] + w`, исключает положительные циклы и отсекает варианты по нижним границам времени.

Сохраняется до шести лучших сочетаний. При равном общем времени не гарантируется минимальная сумма ожиданий, а равные альтернативы могут отсекаться. Оптимальность относится к данной модели и простым маршрутам. Каждый результат проходит независимую проверку конфликтов. Внутри используются дробные секунды и допуск `1e-7`; округление — только для экрана.

## Классы и функции

Исходники находятся в `src/train`, пакет `train`.

| Класс | Ответственность и методы |
|---|---|
| `Main` | `main`: запуск Swing в EDT; `--demo`: консольный расчёт |
| `Model` | Record-классы данных: `Edge`, `Train`, `Config`, `Interval`, `Dwell`, `Segment`, `Schedule`, `Conflict`, `Plan`, `SearchResult`; `defaults`: исходные параметры; `key`: общий ключ ребра |
| `Network` | Конструктор: граф; `paths` / `dfs`: поиск путей; `edge` / `length`: участки и длины; `validate` / `validateRoute`: ввод и маршруты |
| `TimeUtil` | `parse`: разбор; `format`: округлённый вывод; `exact`: дробные секунды |
| `Scheduling` | `build`: базовое движение; `conflicts`: пересечения; `withWaits`: повторный расчёт ожиданий; `plan`: итоговое время |
| `Scheduling.Motion` | Точки движения головы и хвоста; `point`: поиск точки; `materialize`: расписание из временных переменных |
| `Optimizer` | `search`: сочетания и шесть результатов; `solve`: ветви и границы; `finish`: срок освобождения; `shift`: сдвиг графика; `checkInterrupted`: отмена |
| `SimulatorFrame` | Окно; `readConfig`, `number`, `integer`, `text`: ввод; `startSearch`: фон; `checkManual`: проверка; `apply`: вариант; `displayPlan`: результат |
| `SimulatorFrame`, вспомогательные методы | `invalidateInputs`: сброс; `comparisonKey`, `updateComparison`: сравнение; `showTime`, `advanceAnimation`: время; `setBusy`: блокировка ввода; `showError`: ошибки; `loadDefaults`, `randomize`: данные; `readOnly`: модель таблицы |
| `NetworkPanel` | `paintComponent`: рисунок; `occupied`: занятость; `drawTrain`: движение; `display`: обновление |
| `TimelinePanel` | `paintComponent`: временная диаграмма поездов; `display`: выбранный план; `fill`: интервалы на шкале |
| `SelfTest` | Регрессионные проверки и независимый полный перебор малых задач |
| `UiSelfTest` | Проверка обработчиков Swing, режимов, выбора, ручной проверки, сброса и рендер окна |

В Java символ `#` сам по себе не начинает комментарий. Использован правильный синтаксис **`// #Название: объяснение`** рядом с классами, основными методами, существенными этапами алгоритма, обработчиками и обработкой ошибок. Метки удобно искать по `#` в IDE.

## Сборка и проверка

```powershell
# Сборка и алгоритмические проверки
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test

# Проверка интерфейса (нужна графическая среда)
java '-Dfile.encoding=UTF-8' -cp out train.UiSelfTest

# Консольная демонстрация
java '-Dfile.encoding=UTF-8' -jar dist/train-simulator.jar --demo
```

Ручная сборка, например на Linux/macOS:

```sh
mkdir -p out dist
javac --release 17 -encoding UTF-8 -d out src/train/*.java
jar --create --file dist/train-simulator.jar --main-class train.Main -C out .
java -Dfile.encoding=UTF-8 -jar dist/train-simulator.jar
```

Выполнены **1855 алгоритмических проверок**: четыре комбинации режимов, шесть результатов каждого поиска, повторный расчёт хвоста и ожиданий, встречные и попутные конфликты, запас, длинный хвост, изменение и отключение `E-G`, неправильные данные, нулевая длина. Поиск времени сверяется с полным перебором отправлений и остановок в малых задачах.

| Исходные данные | С остановками | Без остановок |
|---|---:|---:|
| С вагонами | 6072 с = 01:41:12 | 6072 с = 01:41:12 |
| Без вагонов | 6000 с = 01:40:00 | 6000 с = 01:40:00 |

Результаты совпадают с исходным проектом. Для №3 кратчайший путь 50 км при 30 км/ч требует 6000 с; хвост длиной 600 м добавляет 72 с. Найденный план достигает нижней границы 6072 с.

## Защита и ограничения

Дополнительно выполнены **23 проверки интерфейса** с вызовом настоящих обработчиков Swing. Проверка интерфейса создаёт локальный рендер `java-desktop.png`; этот файл не публикуется в репозитории. Во вкладке «График времени» показаны отправления, движение, остановки и выход хвоста на общей шкале.

Сценарий выступления, пример расчёта и ответы на вопросы Java — **[DEFENSE.md](DEFENSE.md)**.

Скорость на участке постоянна; разгон, торможение и вместимость станций не моделируются. Ожидающие отправления составы стоят вне сети. За конечной станцией предполагается свободный выход. Геометрия и нарисованный хвост условные; занятость считается по физической длине. Интерфейс перенесён в настольное окно Swing. Точный поиск в изменённых сложных задачах может быть длительным, предусмотрена отмена. Данные хранятся в памяти до закрытия окна; сохранение в файл не предусмотрено.
