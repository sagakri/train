# Симулятор движения поездов

Автономное приложение на HTML, CSS и JavaScript для задачи об однопутной железнодорожной сети в форме X.

## Как открыть

Откройте `index.html` в браузере. Сервер и сборка не нужны; файлы подходят для GitHub Pages.

## Принятые исходные данные

- Основные рёбра: A-E, E-O, O-S, S-C, D-F, F-O, O-G, G-B.
- Дополнительные соединения: E-F, E-G, F-S, G-S (по 2 км). Обе боковые связи E-G и F-S подтверждены последними уточнениями пользователя.
- Центральная точка «0» из голосового уточнения соответствует узлу O (латинская буква) в программе. A-O = 25 км, A-E = 23 км, E-O = 2 км. E-G моделируется отдельным соединением, не маршрутом E-O-G длиной 4 км; O входит только в маршруты, в которых указан явно.
- A-E, B-G, C-S, D-F = 23 км.
- E-O, F-O, G-O, S-O = 2 км.
- E-F = G-S = 2 км.
- Каждое полное плечо до O равно 25 км (23 + 2). Геометрия рисунка условная, не в масштабе.
- `ц` трактуется как цистерны, `в` как вагоны; поле трактовки можно изменить.
- Длина вагона и цистерны по умолчанию равна 20 м. Это предположение, потому что численное значение `l0 = const` в условии не задано.
- Запас безопасности по умолчанию равен 1 секунде.

## Что считает приложение

Для каждого поезда строится маршрут по включённым рёбрам графа. Время движения головы по участку считается как `3600 * d / v`, где `d` в километрах, `v` в км/ч. Хвост освобождает ресурс позже на `3.6 * L / v`, где `L` — длина состава в метрах.

Проверяются интервалы занятости:

- однопутных рёбер, независимо от направления движения;
- стрелок и конечных узлов как точечных ресурсов;
- с учётом общего запаса безопасности.

Ручной режим проверяет введённые времена отправления и сохраняет ожидания выбранного расчётного варианта. Автоматический режим перечисляет все сочетания простых путей без повторного посещения узлов. Метод ветвей и границ рассматривает оба порядка занятия каждого конфликтующего ресурса и минимизирует время освобождения сети хвостом последнего поезда. Сочетания, которые не могут улучшить шесть найденных результатов по нижней границе времени, отсекаются. При равенстве общего времени не гарантируется минимальность суммы ожиданий.

Два режима: «Без остановок в пути» разрешает ожидать только перед отправлением; «С ожиданием у стрелок» разрешает также остановки головы поезда в промежуточных узлах. Скорость на участке постоянна, разгон и торможение не моделируются. Время выхода хвоста вычисляется по движению головы на расстояние длины состава, включая все промежуточные ожидания. Поэтому остановившийся поезд продолжает занимать стрелку и предыдущие участки, пока их не освободит его хвост. После конечной станции предполагается свободный выход состава за границу сети. Ожидающие отправления составы находятся вне сети.

Все рёбра двунаправленные. Однопутность означает исключительное занятие ресурса одним составом: встречный и попутный второй поезд ждут до выхода хвоста первого плюс запас безопасности. Геометрия линий не создаёт дополнительных узлов; E-G является отдельным ребром, а не проходом через O. Ограничения решаются распространением нижних границ, положительные циклы исключаются. Введённые ручные времена и маршруты не ограничивают автоматический поиск.

Результаты проходят отдельную проверку конфликтов. Показываются до шести лучших сочетаний маршрутов с оптимальными отправлениями для каждого. Оптимальность относится к этой модели и простым путям. Вычисления используют неокруглённые секунды с допуском 1e-7 с; время на экране округлено. При изменении параметров результаты сбрасываются.

## Проверки

Рядом с расчётом есть переключатель «С вагонами / Без вагонов». В первом режиме учитывается исходная длина состава; во втором расчётная длина всех поездов равна нулю, включая условный локомотив. Сохранённые количества вагонов и цистерн не меняются. Скорости, сеть, направления, однопутные ограничения и запас безопасности сохраняются. После переключения запускается обычная команда «Найти лучший график». Результаты двух режимов для одинаковых параметров показываются рядом; изменение параметров или режима ожидания исключает устаревшие результаты из сравнения.

На исходных значениях минимум с вагонами — 01:41:12, без вагонов — 01:40:00 (разница 72 с). Это верно для обоих режимов ожидания. Проверены нулевая задержка хвоста, сохранность введённых составов, встречная/попутная блокировка, защитный интервал и возврат к исходному результату.

`node test.cjs`: сверка с полным перебором малой задачи, оба режима поиска, двунаправленные конфликты, повторный расчёт ожиданий и освобождения хвоста, отсутствие пропущенных сочетаний, редактирование E-G.

`node test-ui.cjs`: браузерные проверки через Playwright и установленный Microsoft Edge; при необходимости путь к пакету Playwright задаётся переменной `PLAYWRIGHT_PATH`.

Перечень всех маршрутов и рассчитанный график находятся в `ROUTES.md`.
