# Подготовка к защите Java-проекта

## Короткое выступление

«Мой проект моделирует четыре поезда на однопутной железнодорожной сети. Нужно выбрать маршруты, отправления и ожидания у стрелок так, чтобы ресурсы не занимались двумя составами одновременно и сеть освободилась как можно раньше.

Приложение реализовано на Java 17. Swing отвечает за окно и анимацию. Данные отделены от графа, расчёта расписаний и оптимизатора. Каждый участок и узел считается ресурсом, который освобождается только после выхода хвоста. Поэтому безопасность учитывает длину состава.

DFS перечисляет простые маршруты, а метод ветвей и границ выбирает порядок доступа к конфликтующим ресурсам. Результаты дополнительно проверяются отдельным методом. Для исходных данных минимум равен 6072 секундам с вагонами и 6000 без вагонов. Эти результаты подтверждены нижней границей по самому медленному поезду и автоматическими проверками».

## Что показать

1. Запустить `run.bat`, показать сеть и характеристики поездов.
2. Нажать «Проверить отправления» при исходных нулевых отправлениях: показать конфликты во вкладке проверки.
3. Нажать «Найти лучший график»: показать 01:41:12 и отсутствие конфликтов.
4. Во вкладке расписания показать ожидания №1 в O и №4 в G.
5. Запустить анимацию, поставить паузу, передвинуть ползунок; оранжевые ресурсы заняты.
6. Выбрать другой вариант и выполнить ручную проверку: рассчитанные ожидания сохраняются.
7. Снять «С вагонами», выполнить поиск: показать 01:40:00 и сравнение.
8. Восстановить исходные данные, выбрать «Без остановок в пути»: показать задержанные отправления.
9. Открыть `Main`, `Network`, `Scheduling`, `Optimizer`, `SimulatorFrame` и объяснить метки `#`.

Редактирование ячеек сбрасывает сохранённые ожидания, поэтому ручную повторную проверку выбранного плана показывайте до редактирования.

Для демонстрации изменяемого направления выберите в столбце «От» другую станцию, затем откройте список «Маршрут». Выберите доступный путь — режим станет «Заданный», и поиск будет оптимизировать времена с сохранением этого пути. Нажмите «Поменять направление выбранного поезда»: станции и заданный путь развернутся. Режим «Авто» возвращает полный поиск путей. Фиксированные пути передаются в дополнительный вариант метода `Optimizer.search` как соответствие номера поезда и списка узлов; `Network.validateRoute` проверяет станции и доступность рёбер.

## Пример расчёта

Поезд №3: 30 цистерн по 20 м, скорость 30 км/ч, маршрут `A-E-O-S-C`.

```text
Длина состава = 30 * 20 = 600 м.
Длина маршрута = 23 + 2 + 2 + 23 = 50 км.
Время головы = 3600 * 50 / 30 = 6000 с.
Задержка хвоста = 3.6 * 600 / 30 = 72 с.
Освобождение сети = 6072 с = 01:41:12.
```

На `A-E` голова находится с 0 до 2760 с, хвост освобождает участок в 2832 с. При запасе 1 с другой поезд допускается на участок не раньше 2833 с.

Конфликт двух интервалов одного ресурса:

```text
max(startA, startB) < min(endA + gap, endB + gap) - EPS
```

`EPS = 1e-7` учитывает погрешности вычислений дробных секунд. Округление происходит только на экране.

## Объяснение алгоритма

**Граф и рекурсия.** Вершины — станции и стрелки, рёбра — участки с длинами. `Network.dfs` добавляет соседний узел к пути, рекурсивно продолжает поиск и удаляет его при возврате. Уже посещённые узлы пропускаются.

**Временные переменные.** Без остановок неизвестно только отправление каждого поезда. С остановками `Scheduling.Motion` добавляет точки прихода и ухода головы и освобождения хвостом. В промежуточном узле уход может быть позже прихода. Время движения между точками фиксировано двумя границами:

```text
t[b] >= t[a] + duration
t[a] >= t[b] - duration
```

Вместе это равенство `t[b] = t[a] + duration`. Ожидание разрешается в узлах, постоянная скорость сохраняется между ними. Если голова остановилась, хвост тоже остановился: предыдущие ресурсы освобождаются позже.

**Ветви и границы.** При конфликте создаются два порядка: A перед B и B перед A. Ограничение требует входа второго после выхода первого плюс запас. Нижние границы времён распространяются до стабилизации. Положительный цикл означает невозможный график. Ветвь, уже не улучшающая результат, отсекается.

**Полнота.** Учитываются все 5184 исходных сочетания простых маршрутов. Некоторые отсекаются без поиска времени, когда их нижняя граница уже не улучшает шестой сохранённый результат. Это не случайная выборка.

**Независимая проверка.** `Scheduling.conflicts` сравнивает готовые интервалы, не используя ограничения оптимизатора. `SelfTest` дополнительно сверяет оптимизаторы с полным перебором малых задач.

## Вопросы по Java

| Вопрос | Ответ |
|---|---|
| Где точка входа? | `Main.main(String[] args)` |
| Почему несколько классов? | Разделены данные, граф, время, расчёт, поиск, интерфейс, рисунок и проверки |
| Что такое record? | Компактный класс данных с final-полями и автоматически созданными конструктором, методами доступа, equals, hashCode, toString |
| Record полностью неизменяемый? | Поля final; вложенные коллекции могут быть изменяемыми. Config копирует списки через List.copyOf |
| Для чего List, Map, Set? | List — маршруты и события; Map — связи узлов; Set — уникальные узлы и временные точки |
| Где рекурсия? | `Network.dfs` |
| Где стек? | ArrayDeque в Optimizer хранит альтернативные ветви |
| Почему double? | Расчёты дают дробные секунды; целые числа теряли бы точность |
| Что делает static? | Утилитарный метод вызывается без экземпляра, например TimeUtil.format |
| Зачем private? | Скрывает детали реализации, например поля окна |
| Где наследование? | SimulatorFrame extends JFrame, NetworkPanel extends JPanel |
| Что делает Override? | Помечает переопределение метода родителя, например paintComponent |
| Где полиморфизм? | Компоненты используются через Component; собственные модели Swing вызываются через базовые API |
| Для чего try/catch? | Неправильный ввод и ошибки поиска показываются пользователю вместо аварийного закрытия |
| Для чего finally? | Восстанавливает доступность элементов после поиска при любом исходе |
| Что такое EDT? | Поток событий Swing, в котором создаются и обновляются компоненты |
| Зачем SwingWorker? | doInBackground считает в фоне, done обновляет окно в EDT; интерфейс не зависает |
| Как отменяется поиск? | cancel(true) прерывает поток, оптимизатор проверяет флаг между ветвями и сочетаниями |
| Почему восстанавливается флаг InterruptedException? | Чтобы информация о прерывании не потерялась после перехвата |
| Что такое лямбда? | Краткая функция, например обработчик `e -> startSearch()` |

## Где обработаны ошибки

- `Main`: недоступная системная тема заменяется стандартной темой Swing.
- `SimulatorFrame.number`: неправильное число превращается в понятную ошибку ввода.
- `startSearch`, `checkManual`: неверные параметры показываются через `showError`.
- `SwingWorker.done`: отдельно обрабатывает отмену, прерывание и исключение фоновой задачи; `finally` восстанавливает кнопки.
- `invalidateInputs`: незавершённый ввод временно не вызывает диалог на каждый символ.
- `SelfTest`: намеренно передаёт NaN и проверяет, что валидация его отвергает.

## Какие утверждения корректны

Оптимальность относится к описанной модели и простым путям. Скорость постоянна, разгон, торможение и вместимость станций не моделируются. Минимизируется освобождение сети, а не сумма ожиданий. При одинаковом общем времени допустимы разные графики. Рисунок не в масштабе.

Происхождение проекта можно объяснить точно: исходная версия была на HTML/CSS/JavaScript, текущая переносит расчёты и интерфейс в самостоятельное Java-приложение. На защите нужно уметь проследить путь от ввода через граф и поиск до проверки результата.
